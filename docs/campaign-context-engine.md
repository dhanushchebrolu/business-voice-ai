## 2. Gaps found

1. **Safety (dispatcher)**: platform calling hours (09–21 IST) and the +91-only rule (`staticEligibilityBlocker`) are enforced on single calls but **not** on campaign calls; a campaign with an empty schedule is "always callable" in UTC.
2. **Wallet**: campaign dial checks the balance for one call, ignoring other open calls (single or campaign); single-call admission ignores open campaign calls.
3. **No per-customer in-flight limit** for campaign calls.
4. **No campaign budget** (spending cap).
5. **No structured context**: free-text objective/instructions only, editable after review through direct column grants; no review step.
6. **No eligibility preview** (excluded contacts and reasons) before launch.
7. **Reporting**: no outcome breakdown, spend or budget.
8. Experimental `sarvam_campaign` mode: off by default, known gap (no per-contact results) — unchanged.

## 3. Plan (reuse first)

- **Context engine** (`campaign-context.ts`, pure): versioned structured context (objective, reason, audience, opening, talking points, questions, desired outcome, objection handling, callback handling, closing, tone, extra instructions, success criteria). Validation and length limits; a deterministic compiler into the two verified variables (`campaign_objective`, `campaign_instructions`). Allowed/forbidden actions come from the agent role (`OUTBOUND_AGENT_TOOLS` / forbidden list), shown in review, never customer-editable, and never compiled as permission.
- **Drafting**: an optional LLM pass (existing `claude.server.ts`, only if `ANTHROPIC_API_KEY` is set) turns the plain description into a draft at preparation time; output is parsed and validated like any customer input; without a key a deterministic draft is used. The original description is stored unchanged.
- **Review gate**: `context`, `context_reviewed_at` are server-written only; launch requires a reviewed context; the dispatcher passes the compiled values from the reviewed context, not the free-text columns.
- **Admission**: one SQL function `admit_campaign_outbound_call` (same lock and pattern as `admit_single_outbound_call`): campaign still running, in-flight limit across the customer, wallet worst case over **all** open outbound calls, campaign budget (spent + open reservations), then inserts the call row (number reservation → `destination_busy`). Single admission is updated to count open campaign calls too.
- **Dispatcher**: platform eligibility per run and per contact (hours, +91, kill switch); non-+91 contacts are marked `excluded` with a reason; admission via the new function.
- **Eligibility preview** and **richer stats** (outcome categories, spend, budget) as server functions; UI: description → prepare → review/edit → save; budget; dashboard breakdown.
- **Tests**: unit (context, compiler, separation, outcomes, eligibility), dispatcher behaviour (hours, +91, budget, wallet, in-flight, context per campaign), PostgreSQL (admission function).

Not changed: the Sarvam agent, its prompt and tools; no deploy, no migration applied to production, no calls.
